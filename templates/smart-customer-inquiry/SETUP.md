# Setup

## Quick start requirements

- n8n **2.45.0 or later**. The earlier v1.1 workflow was manually imported by the operator on self-hosted n8n 2.46.7; this v1.1.1 patch still requires the isolated runtime acceptance test in [TESTING.md](TESTING.md).
- The built-in Form Trigger, Data Table, Schedule Trigger, Code, Switch, If, and Send Email nodes, plus one SMTP credential.
- A test Data Table and test-only internal recipient mailbox. Slack is optional and remains disabled.

## Mandatory setup

1. In a non-production n8n project, import `workflow.json` from **Workflows → Import from File**. Keep it inactive. If you imported an earlier copy of this template, import this corrected file as a new workflow; n8n does not automatically update imported workflows.
2. Open **Data Tables** in the same project and create a table named `customer_inquiries`. Add every column shown below with the stated type. Copy its ID from the table URL/UI.
3. In all eight Data Table nodes, replace `REPLACE_WITH_DATA_TABLE_ID` with that table ID. Keep the column names exact so automatic mapping works.
4. Open **Normalize, validate & classify (CONFIG HERE)** and update the plain `cfg` values. Set the workflow timezone in workflow settings. The timezone governs the schedule display/execution, but the reminder intervals remain elapsed hours rather than business hours.
5. Create an SMTP credential in n8n. Select it in both Send Email nodes, then replace the example sender, internal recipient, and escalation recipient addresses. If the escalation recipient should be the same team, deliberately set both placeholders to the same internal address. Do not use the submitted customer's address as an internal recipient. The reminder node's one recipient expression deliberately selects the ordinary or escalation recipient.
6. In **Customer inquiry form**, replace the generic form description with your own accurate privacy information. If you have a privacy notice, add its HTTPS URL using the Form Trigger's supported rich text/HTML description; do not add a link until the business has a real notice. This required acknowledgement is for handling the inquiry, not marketing consent.
7. To start an intake test, select **Customer inquiry form** and click **Execute step** (or **Execute workflow**). Submit the Test URL opened by n8n. This is the upper branch. The lower scheduled branch cannot be started from the form; execute **Hourly follow-up check** only after a test row exists.
8. In **Data Tables**, change a row status to `Acknowledged`, `In progress`, `Waiting for customer`, `Resolved`, or `Closed`. Update `last_activity_at` when a person acts. Do not reopen Closed records.
9. For a reminder test, set an open test row's `next_reminder_due_at` in the past, `reminder_count` below `3`, and `status` to `New`, then manually execute from **Hourly follow-up check**. Inspect **Explain reminder eligibility** before checking the email and updated next due date.
10. Publish the workflow and use the Form Trigger's production URL only after the preceding checks pass. Schedule triggers require publishing.

## Optional Slack alerts

Slack is deliberately disabled and does not block the default SMTP workflow.

1. Create a test Slack credential with permission to send messages to a test channel.
2. Select **Optional Slack alert — enable after setup**, attach the credential, and replace `REPLACE_WITH_SLACK_CHANNEL_ID`.
3. Enable that node, then change the boolean expression in **Slack enabled for High/Critical?** from `false` to `true`.
4. Submit a High or Critical synthetic inquiry and verify the Slack message contains only the ID, priority, category, subject, submission time, and owner.
5. Test a failed Slack credential in the isolated environment. Leave Slack disabled if it is not wanted.

## Table schema

| Column | Data Table type | Purpose |
| --- | --- | --- |
| `inquiry_id` | String | Human-readable unique best-effort identifier. |
| `full_name`, `email`, `phone`, `company` | String | Contact fields; keep access restricted. |
| `category`, `subject`, `message`, `preferred_contact_method` | String | Inquiry content and stated preference. |
| `consent` | Boolean | Privacy acknowledgement received with the submission. |
| `priority`, `status`, `assigned_owner`, `source` | String | Operational routing and lifecycle. |
| `submitted_at`, `last_activity_at` | Date | Required ISO-8601 timestamps generated by the workflow. |
| `last_reminder_at`, `last_duplicate_at`, `last_retry_at`, `resolution_at` | Date | Optional timestamps. Leave cells empty in the UI; the workflow sends `null` until a value exists. |
| `follow_up_due_at`, `next_reminder_due_at` | Date | Initial and next stage due timestamps. The scheduled branch uses `next_reminder_due_at`. |
| `reminder_count`, `reminder_stage`, `notification_attempts`, `reminder_retry_count` | Number | Counts of successful reminder stages, initial notification attempts, and failed reminder delivery attempts. Retry count includes the original failed delivery. |
| `notification_state`, `last_notification_outcome`, `processing_state`, `error_state`, `escalation_state`, `delivery_failure_state`, `last_retry_error` | String | Processing/audit state. `provider_accepted` means SMTP accepted the request, not inbox delivery. |
| `duplicate_of`, `dedupe_key` | String | Duplicate handling; treat dedupe key as personal data. |

Do **not** add `duplicate_window_start` to the Data Table. It is a temporary query helper, removed by **Remove temporary duplicate-window value** before a record is stored.

## Optional hardening

- Put the public form behind your site, reverse proxy, CAPTCHA/WAF, rate limit, and privacy notice. **Ignore Bots** is enabled but is not an abuse-prevention system.
- Use a dedicated least-privilege SMTP account. Restrict project membership because Data Tables are project-visible.
- Set a data-retention/deletion procedure. Export then securely delete old rows after the required retention period.
- Add a separate Error Trigger workflow to notify an operator using an internal, non-PII execution reference. Do not make it call this workflow recursively.

## Recovery

Storage errors stop the relevant execution before an alert is sent. SMTP nodes use continue-on-fail so the saved row is retained. Reminder delivery failure 1–2 becomes `retry_pending` and is retried after 60 minutes without changing `reminder_stage` or `reminder_count`; failure 3 becomes `delivery_failed` and stops automatic sends. Inspect **Executions**, correct the credential or table issue, then read the current row before acting. To resume a terminal reminder safely, set `delivery_failure_state` to `none`, `reminder_retry_count` to `0`, clear `last_retry_error`, and set `next_reminder_due_at` to a controlled future/past test time. Do not lower `reminder_stage` or `reminder_count`, and do not retry a whole intake execution blindly without checking whether a row already exists.
